# Docker image is multi-arch on GHCR with a PUID/PGID entrypoint

The project ships a container image published to GitHub Container Registry at `ghcr.io/noahbaculi/missing-ebooks`, built for `linux/amd64` and `linux/arm64`, and a `docker-compose.yml` that pulls it. Publishing fires on a `v*` git tag and produces the semver tags (`{{version}}`, `{{major}}.{{minor}}`, `{{major}}`) plus `latest`. This is the path most self-hosters expect, and it lets them run the tool without a Rust toolchain.

The image is built on native runners, one architecture each (`ubuntu-24.04` and `ubuntu-24.04-arm`), and the two results are merged into one multi-arch tag with `docker buildx imagetools create`. The alternative, a single `buildx` job emulating arm64 under QEMU, compiles Rust far slower; native runners are free for public repositories and avoid the emulation tax, so they are the better default.

The runtime image is Alpine with the binary compiled against musl, kept small by copying only the static binary and an entrypoint into the final stage. The entrypoint drops from root to a configurable `PUID`/`PGID` with `su-exec` before launching the server. The app writes marker files into the mounted library, so the writing user must match whoever owns that library on the host; the LinuxServer.io-style PUID/PGID pattern is what self-hosters reach for to line those up, and it sidesteps the permission friction of a UID baked into the image.

Inside the container the server binds `0.0.0.0`, because loopback would be unreachable from the host; exposure is controlled at the port-publish layer and the shipped compose file binds the host port to `127.0.0.1` given the app has no authentication (see ADR 0003 and ADR 0011). Configuration uses the existing env vars for the common knobs, and the entrypoint auto-detects a `config.toml` mounted at `/config/config.toml` for the file-only settings, preserving the env-over-file layering from ADR 0004.

Sources: the Docker docs on multi-platform images ([build by digest and merge](https://docs.docker.com/build/ci/github-actions/multi-platform/)), the GitHub Actions native arm64 runner availability, and the `su-exec` / LinuxServer.io PUID/PGID convention.
